# キャラクター 実装の手引き

Cooltime のメニューバーに出すキャラクターの、絵と動きの元データです。
要件は `../REQUIREMENTS.md` の「14. キャラクター」。ここは「どんなデータがあって、どう使うか」の手引きです。
**描き方・動かし方（言語、描画方法）は、Claude が決めてよい**ものです。理由を添えて提案してください。

> この手引きの絵は、画面イメージ用に作ったSVGです。Swift で描いて動かすところは、まだ誰も試していません。
> 実機で見て、見え方・電池・動きの自然さを確かめてください。

## 1. 中身

```
characters/
├─ CHARACTERS.md        この手引き
├─ motion.json          動きの数値（状態ごと・パーツごと）
├─ preview.html         ブラウザで開くと、全キャラの動きが見られる（ライト／ダーク、大きい表示と18px）
├─ menubar/             メニューバー用SVG（細部を省いた版）  {id}-{state}.svg
├─ large/               大きい表示用SVG（細部つき。設定画面など） {id}-{state}.svg
└─ appicon-candidates/  アプリアイコンの候補（1024px、「制限なし」の絵）
```

- `id`：`bunny`（うさぎ）、`cat`（ねこ）、`bear`（くま）、`pig`（ぶた）、`frog`（かえる）
- `state`：`limit`（制限中）、`ok`（制限なし）、`fail`（すべて取得に失敗）
- 5種類 × 3状態 × 2版 = 30枚。

## 2. SVGの約束事

- 座標は `viewBox="-6 -6 112 112"`。体は 0〜100 の中に収まり、「z」や耳の先が少しはみ出すので、周りに6の余白がある。
- 5種類とも、体（お化けの形、裾は波）は共通。耳（かえるは頭の上の目）が違う。
- `menubar/` の本体は `fill="currentColor"`。**テンプレート画像（1色）として描く前提**。
- **`data-cutout="true"` の付いた要素は、「抜き」**（目・鼻・口・耳の内側）。SVGの上では白で描いてあるが、メニューバーでは**透明にくり抜く**。
  - 例外：かえるの「制限なし」では、目の白いリングが抜き、中の黒い点（`currentColor`）は本体と同じ色。
- 動かすためのグループに `id` が付いている：

| id | 中身 | 使う状態 |
|---|---|---|
| `root` | 耳・体・目を全部まとめたグループ | 全部 |
| `body` | 体（と目・鼻） | 全部 |
| `look` | 目のグループ（外側） | ok |
| `eyes` | 目のグループ（内側。まばたき用） | ok |
| `zz` | 「z」の記号 | limit |

- `large/` は、本体 `#141413`、抜き `#ffffff` の固定色。耳の内側などの細部つき。

## 3. 状態と見た目

| 状態 | メニューバーの表示 | 形 | 動き |
|---|---|---|---|
| `limit` 制限中 | 「あと43分」 | 耳が縮み、目を閉じ、右上に「z」 | 上下にふわふわ |
| `ok` 制限なし | 「残り62%」 | 耳が立ち、目が開いている | きょろきょろ＋まばたき |
| `fail` すべて取得に失敗 | なし（キャラクターだけ） | 耳が崩れ、目が「×」 | ほぼ止まる。ときどきぷるっと震える |

数値は `motion.json`。5種類とも同じ動きを使う（かえるの `ok` は、目が頭の上にあるので、`look` が頭の上の目ごと動く）。

## 4. 実装の方向（案）

どちらでもよい。実機で見て決めてください。

**A. コードで描く**：SVGの形（楕円・多角形・パス）を、Core Graphics などのコードにして、毎コマ、変形をかけて描く。
抜きは「消す」描画で表現する。動きの調整がしやすい。

**B. 画像を書き出す**：スクリプトで、動きの各コマを、1色のPNG（@1x／@2x、高さ18pt）に書き出して、素材に入れる。
実行時の計算がほぼ要らない。コマ数は増える。

どちらの場合も：

- メニューバーには `NSStatusItem` を使い、画像と文字（「あと43分」）を並べる想定（`MenuBarExtra` のラベルは、動きが安定しないことがある）。
- 画像は `isTemplate = true`（1色。ライト／ダークに自動で合う）。
- コマ送りは**1秒に8コマまで**。描いた画像は使い回す。
- 画面がスリープ／メニューバーが隠れたら止める。低電力モードは静止かまばたきだけ。「視差効果を減らす」は静止。
- 設定：動く（既定）／ときどきだけ／止める。

## 5. 確かめてほしいこと（実機）

1. 18ptで、3つの状態がひと目で見分けられるか（特に、ねこ・ぶたの `limit` と `fail`）。
2. 動いて見えるか。動きが大きすぎ・小さすぎないか（`motion.json` の数値を調整してよい）。
3. アクティビティモニタの「エネルギー影響」が高くないか。測った数字を README に書く。
4. ライト／ダークの両方で、抜き（目・鼻）が見えるか。
5. ぶた・くまの鼻、かえるの目のリングが、18ptで潰れていないか。潰れるなら、メニューバー用だけ省く。

## 6. 決まっていないこと

- アプリアイコンの絵（`appicon-candidates/` は、ただの候補。角丸は Xcode 側でかかる）。
- 復旧の目安を過ぎたときの、メニューバーの表示（要件に「未決定」と書いてある）。
- 5種類のうち、既定をどれにするか（いまはうさぎ）。

## 7. 注意

- キャラクターや、アプリのアイコンに、他社のロゴを入れない。
- ほかの動物（きつね・いぬ）は、検討した結果、入れていない。
